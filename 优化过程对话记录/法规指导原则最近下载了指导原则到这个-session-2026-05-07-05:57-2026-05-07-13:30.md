## 实际去重逻辑（`check_duplicate_by_hash`）

```
1. 标题相似度判断 (_title_similarity_level)
   ├── identical → 比哈希
   ├── small（LCS相似率≥75%，如"试行版"vs"正式版"）→ 比哈希
   └── large → 跳过哈希比对（避免大差异标题碰巧哈希相同的误判）

2. 哈希比对（仅标题为 identical/small 时）
   └── 必须 page1哈希匹配 AND page2哈希匹配 → 才判定为重复
```

---

## 结论

**该功能已完整实现**，且比原要求更完善——加入了标题相似度作为前置过滤，避免了两件事：
1. 不同文件碰巧封面相同导致的假误判
2. 同一文件不同版本（征求意见稿 vs 正式版）被错误去重

当前代码版本 `v2.14.0` 的去重策略总结：**标题必须相似 + 两页内容必须一致**，才能认定为重复文档。

## 表格提取现状

---

### 文件类型处理方式

| 文件类型 | 表格提取方式 | 合并单元格支持 |
|---------|------------|-------------|
| **Excel (.xlsx)** | openpyxl 库，精确读取 colspan/rowspan | ✅ 完整还原 |
| **Word (.docx)** | python-docx，读取 gridSpan + vMerge 属性 | ✅ 完整还原 |
| **数字 PDF** | opendataloader → PDF Plumber → 扁平 table_data | ❌ 无法精确还原 colspan/rowspan |
| **扫描 PDF（qwen2.5vl OCR）** | qwen2.5vl 图像识别 → 扁平 table_data | ❌ 无法精确还原 colspan/rowspan |

---

### 关键限制

**数字 PDF 和扫描 PDF 都输出的是扁平 table_data**，合并单元格只能通过启发式推算（`_detect_merged_cells_from_flat`）：
- 某行 cell 数 < 最大列数 → 猜测有横向合并
- 相邻两行某列内容完全相同 → 猜测有纵向合并

但具体 `colspan/row_span` **数值无法精确还原**。

---

### 渲染 Markdown 时的处理

`_table_to_markdown_with_spans()` 会：
- **横向合并**：在对应位置填满空列
- **纵向合并**：在续行位置填入 `^`（Markdown table rowspan 扩展惯例）

```
| A   | B   | C   |
| ^   | 值1 | 值2 |   ← "^" 表示纵向合并
```

---

### 结论

| 场景 | 合并单元格信息完整性 |
|------|-----------------|
| Excel / Word | ✅ 完整保留 |
| 数字 PDF | ❌ 丢失（只能推算有无合并，无法精确到 colspan/row_span 数值） |
| 扫描 PDF（qwen2.5vl） | ❌ 同样丢失 |

如果需要精确保留 PDF 中表格的合并单元格信息，目前只能通过 **qwen2.5vl OCR 逐页识别** 来改善，但本质上图像识别也很难输出精确的 colspan/row_span——它只能输出扁平文本。这是个业界难题，PDF 本身的表格就是"视觉对齐"而非"结构化数据"。
